About

I work where machine learning meets security operations. Day to day that means the pipelines and evaluation layers threat teams rely on: moving raw threat and vulnerability data through ingestion, normalization, enrichment, and detection, then layering models on top that analyze cases and drive response.

A confident wrong answer in security is worse than no answer, so a lot of my work is the verification and guardrails around a model, not just the model itself. That is the difference between a demo and something an analyst will actually trust.

Writing

detection engineering

Detection that doesn't fire on a normal Tuesday

Anyone can catch an attack in a log full of attacks. The real work is everything you do so it stays quiet on benign traffic.

 identity security

Most companies are not hacked. They are logged into.

MFA helped, so attackers moved to the session token. The question is whether you would notice when one is stolen.

 ai security

The model generates. The harness decides what to believe.

AI engineering for security is less about the model and more about the verification layer you wrap around it.

 ai security

Giving an LLM tools is giving it an attack surface

The moment a model can act, every tool you connect becomes another door someone can try to walk through.

 agent security

Anyone can give an agent tools

The real work is deciding what an agent is allowed to touch, and being able to explain it afterwards.

 ai safety

A fully safe model is a limited one

Safety and capability pull against each other. Maybe that is the part we need to stop pretending about.
